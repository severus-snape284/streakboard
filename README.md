# Streakboard

A personal, mobile-first PWA that shows your [Habitica](https://habitica.com) daily streaks, streak-first.
Keep using the official Habitica app to check things off. Streakboard is the scoreboard.

- Dailies sorted by streak, with a big flame number on each one, today's status, and current / best
- A hero card with your best current streak, how many streaks are active, and how many dailies are still due
- A "streak at risk" banner for dailies with a streak of 3 or more that are due today and not done yet
- A best-streak record that goes back through Habitica's history (not just from install day), plus a history of streak breaks
- A detail page per daily with a calendar heatmap, stats and milestone progress (7 / 21 / 30 / 66 / 100 / 365)
- **Tick dailies off right in Streakboard** (and checklist items). Updates instantly, is undone if Habitica rejects it, and asks before unticking
- **Streak rescue**: when Habitica's new day hasn't started yet, ticks still count for yesterday. Tick what you did, then tap **Start my new day**
- **Time left today** countdown and a progress ring of today's due dailies
- **"Don't miss twice"**: highlights dailies you missed the last time they were due
- **Perfect days**: days when every due daily got done, plus a perfect-day streak
- **Insights tab**: 7 / 30-day completion rate per daily (weakest first), trend vs the previous period, weakest weekday
- **Habits tab**: positive habits with a +1 button and day/week/month streaks (per the habit's reset period)
- **Milestone celebrations** at 7, 21, 30, 66, 100 and 365 days
- Optional **app icon badge** with the number of dailies still due (iOS 16.4+, needs notification permission)
- Pull-to-refresh, opens offline, last-updated timestamp
- Export / Import a JSON backup

No build step and no runtime dependencies: just vanilla JS ES modules, HTML and CSS.

## Get your Habitica User ID and API token

Habitica (web) → **Settings → Site Data → API**. Copy the **User ID** and click **Show API Token**.
On first launch Streakboard asks for both. They're stored only on your device (in `localStorage`) and
sent only to `habitica.com`. Use **Settings → Log out & clear credentials** to remove them.

> The API token gives full access to your Habitica account, so treat it like a password.

## Install on iPhone (iOS 16.4+)

1. Open the site in **Safari**: `https://<your-github-username>.github.io/streakboard/`
2. Tap **Share** → **Add to Home Screen** → **Add**.
3. Open Streakboard from the Home Screen and enter your User ID and API token.

## Local development

```sh
python3 -m http.server 8080      # or: npm run serve
# open http://localhost:8080/
npm test                         # unit tests (Node 18+)
npm run e2e                      # Playwright end-to-end check at an iPhone viewport (mocked API)
```

`npm run e2e -- <dir>` also saves screenshots to `<dir>`. The service worker caches the app shell, so
after editing files, hard-reload. When you release, bump `VERSION` in `sw.js` so installed copies update.

Icons are placeholders generated by `python3 tools/make_icons.py` (needs Pillow).

## Deployment (GitHub Pages)

Every push to `main` runs `.github/workflows/pages.yml`: unit tests, then it copies the app files and
deploys them to Pages. One-time setup: **Settings → Pages → Build and deployment → Source = GitHub Actions**.
The app is served from `/streakboard/`, so every URL in the app is relative.

## Why there's no proxy (CORS)

Habitica's API sends `Access-Control-Allow-Origin: *`, allows the `x-api-user` / `x-api-key` / `x-client`
headers, and exposes the `X-RateLimit-*` and `Retry-After` headers. That means the browser can call it
directly. A proxy wouldn't make a single-user app any safer, because the device has to hold a credential
either way. It would just add a server to run and one more party that sees your token.

## How streaks are computed

- **Current streak, due today, done today** come straight from Habitica (`streak`, `isDue`, `completed`).
  Streakboard doesn't reimplement Habitica's scheduling.
- **Best streak** is the highest of three numbers: Habitica's current streak, the longest run rebuilt from
  each daily's `history`, and the highest streak Streakboard has seen in past fetches.
  Rebuilding from history works because of how Habitica writes it: each check-off adds a `completed: true`
  entry, and each cron adds a `completed: false` entry (with `isDue`) only for dailies that weren't done.
  Check-offs made in Habitica's "record yesterday's activity" prompt count for the previous day.
- **Breaks** come from two places: misses found in history, and drops in the streak seen between fetches.
- Days Streakboard has worked out are saved in IndexedDB. Habitica eventually compresses old history,
  but what Streakboard has already seen stays.

## Known limitations

- **Streaks only update after Habitica's cron** (its daily rollover). Opening Streakboard never triggers
  cron: only the official apps or Streakboard's **Start my new day** button do. Until cron runs, Streakboard
  shows the previous day's state, and ticks count for that day.
- **Writes are real.** Ticking in Streakboard changes your Habitica account, including gold, XP and
  streak bonuses, exactly as ticking in the official app would.
- **iOS storage eviction.** iOS can delete website data, especially for PWAs you haven't opened in weeks.
  Streakboard asks for persistent storage, but iOS may ignore the request. Use **Settings → Export backup**
  now and then, and **Import** to restore. Your current streaks always come back from Habitica, but the
  best and break history kept on this device could be lost.
- **History has limits.** Habitica's history only covers days you used it, so days you didn't open
  Habitica show as "no data". Very old history may be compressed and lose its completion details.
- **Rate limits.** Habitica allows about 30 requests a minute. Streakboard makes 3 requests per refresh:
  on open, on pull-to-refresh, and at most every 5 minutes while open. It backs off on `429` using
  `Retry-After` / `X-RateLimit-Reset`.
- **iOS PWA restrictions.** No background refresh. Web Push needs iOS 16.4+ and isn't implemented.
  Home Screen apps keep their own storage, separate from Safari, so enter your credentials inside the
  installed app.
